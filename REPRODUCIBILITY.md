# Reproducing the Lean formalization

## Environment and checkout

Install Git and elan using the [Lean installation guide](https://lean-lang.org/install/manual/).
The automated checks also require Bash (Git Bash or WSL on Windows) and Python
3.11 or later. Use a shell where `git`, `elan`, `lake`, and `python3` or
`python` are on the path. The initial checkout and dependency downloads need
network access.

```bash
git clone https://github.com/WangJiabai/Determinantal-Ideals-Formalization.git
cd Determinantal-Ideals-Formalization
```

For a result cited at a specific revision, run `git checkout --detach <commit-sha>`
with the full SHA from the citation. Record the exact version with
`git rev-parse HEAD`.

| Component | Pin |
| --- | --- |
| Lean and Lake | `leanprover/lean4:v4.28.0` in [`lean-toolchain`](lean-toolchain) |
| Mathlib | `v4.28.0`, commit `8f9d9cff6bd728b17a24e163c9402775d9e6a365` |
| `groebner` | `v4.28.0`, commit `32e5c0d4244f100ac9161642e9b0368277741fbd` |

[lakefile.toml](lakefile.toml) declares the dependencies, and
[lake-manifest.json](lake-manifest.json) pins their resolved revisions. Lake
fetches Mathlib and the other dependencies for this checkout. The cache command
downloads precompiled Mathlib dependencies to speed up the build.

```bash
elan toolchain install leanprover/lean4:v4.28.0
lake env lean --version
lake exe cache get
lake build
```

The proofs use the pinned dependencies and run without an external computer
algebra system.

The first command below prints declaration types and checks selected exact
signatures. The second compiles examples using the concrete order
`antiDiagonalLex`.

```bash
lake env lean PaperAudit.lean
lake env lean Examples/PaperExamples.lean
```

The project treats the ideal generated by the fixed-size minors and its
total-degree Hilbert function. The identification with the vanishing ideal of
the rank variety is not formalized. See the
[statement correspondence](docs/statement_correspondence.md).

## Audit proofs and axiom dependencies

Run the complete verification suite after building.

```bash
bash scripts/check_artifact.sh --skip-build
```

Omit `--skip-build` to let the script run `lake build` as part of verification.
A successful run ends with `Artifact checks completed successfully`. The same
component checks also run in the [Lean CI workflow](.github/workflows/lean.yml).

The individual checks below can be run from the repository root. Use `python`
in place of `python3` if that is the local name for Python 3.11 or later.

| Command | What it checks or reports |
| --- | --- |
| `bash scripts/check_sources.sh` | Scans all Git-tracked Lean files for `sorry`, `admit`, `sorryAx`, and project `axiom` or `unsafe` declarations, including private and protected declarations. |
| `lake env lean Audit.lean` | Prints the transitive axiom dependencies from `#print axioms` for the principal results and selected supporting declarations. |
| `python3 scripts/check_axioms.py` | Runs the axiom report and requires a report for each configured declaration. It rejects `sorryAx` and any axiom outside the allowlist. |
| `python3 scripts/check_paper_contract.py` | Checks consistency between the declared interfaces, audit files, metadata, declaration links, and documented scope. |
| `python3 scripts/paper_links.py --check-only` | Locates the listed declarations and checks Lean source links in this guide, the README, and the project notes. |
| `python3 scripts/artifact_metadata.py --format markdown` | Reports the current commit, working-tree status, toolchain, dependency revisions, and declaration names. |

The link check covers inline Markdown links. It checks file paths and line
bounds, and checks the starting line against the declaration when the link
label names a declaration in the audit list. Other labels receive path and
line checks only. Historical GitHub links are checked against locally
available Git revisions.

For the two Gröbner-basis theorems, the expected dependencies are
`Classical.choice`, `propext`, and `Quot.sound`. These are standard
foundational dependencies in Lean and are listed in
[`audit/axiom_allowlist.txt`](audit/axiom_allowlist.txt). Any additional
dependency, including a project-specific axiom or Lean’s `sorryAx` placeholder,
fails the automated axiom audit. The source scan covers all tracked Lean files,
while the dependency audit follows the proof terms of the declarations listed
in [`Audit.lean`](Audit.lean), including their imported dependencies.

## Record the verified revision

From a clean, committed checkout, generate metadata and source permalinks for
the exact revision used.

```bash
python3 scripts/artifact_metadata.py --require-clean --format markdown
python3 scripts/paper_links.py --format markdown
```

The source links use the full commit SHA. Use the same SHA when citing the
software with [`CITATION.cff`](CITATION.cff).
